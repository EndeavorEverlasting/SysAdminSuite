# Printer field incident — technician agent reception and repair contract

**Owner:** SysAdminSuite Field Workflow. **Parent:** [printer deployment / standard-user regression #548](https://github.com/EndeavorEverlasting/SysAdminSuite/issues/548). **Baseline:** merged #549 on main at `10c222af5a3a04b1041dd4f551515224147ba524` (historical floor, **refresh live main** at intake). **No authorization is inherited from this page.**

## What a technician can say

An agent working in this repository must recognize ordinary phrases such as *"printer doesn't show when the standard user logs in"*, *"SAS printer fallback failed"*, *"the Startup script didn't delete"*, *"mapping completed but the user's queue is missing"*, *"task didn't run"*, *"can't open the printer launcher"*, and the exact **SAS PRINTER INCIDENT** header. Don't demand a prompt number, a ticket ID, a commit SHA, a stack trace, or an agent handoff before starting read-only recovery.

Use `Report-NorthwellPrinter-Issue.cmd` **only if additional bounded local evidence helps**. It is a read-only Windows PowerShell 5.1 field launcher; it creates a private folder in `%LOCALAPPDATA%\SysAdminSuite\Evidence\PrinterSupport`, opens a safe handoff, and leaves both original evidence and field devices unchanged. It works without Git, Python, elevated credentials, or internet access. The operator decides whether to share the sanitized handoff. Never ask for secret credentials, raw user records, screenshots from protected clinical systems, or private fleet logs in public Git/chat.

## The agent's deterministic intake loop

1. **Preserve the question and recover truth.** Classify organization and site explicitly. Confirm Northwell shared-printer use case before using its modes; Agilant local-TCP and H&H clients are different authorities. Read `AGENTS.md`, `CODEBASE_MAP.md`, `harness/api/agent-routing-manifest.json`, this runbook, `harness/api/northwell-printer-session-fallback-modes.v1.json`, and only the selected printer lane of `.claude/skills/field-workflow/SKILL.md`. Check fresh origin/default branch, open printer PRs/issues, recent commits, generated/installed runtime floor, executable CMD, runner code, fixtures, relevant CI, and any existing private evidence *only if the connected runtime is authorized to see it*.
2. **Triage, don't mutate.** Treat tech words as **OPERATOR_REPORTED**. A local `Summary.json` reports prior SYSTEM machine registration, not current standard-user proof. A local user receipt reports an earlier session, not today's other account. No report generated by this tool is live certification. Use `harness/api/printer-field-incident-route.v1.json` to select the known source of truth and the next discriminating read-only check.
3. **Preserve private observations locally once.** Where a typed `finding-input.v1.json` exists, the next *authorized* repo agent may run `harness/api/sas_finding_ingest.py` once in its approved local runtime. That producer is optional if Python is unavailable; the field launcher still succeeds. Event/receipt, raw target identities, HKU SIDs, print UNC, local evidence paths, or screenshots stay operator-local or in an explicitly approved restricted support location. **No automatic Git issue, public PR comment, GitHub Action log, Drive sync or notification service receives private evidence.**
4. **Recovery hierarchy:** M0 SYSTEM `PrintUIEntry /ga` + HKLM authoritative machine registration; M1 current-user InteractiveToken if actually loaded; M2 standard-user next-logon *observation* before workaround; M3 only after evidence of approved driver-readiness issue, never Point-and-Print security weakening; M4 durable user logon Task Scheduler and its C$-independent TaskShareless alternative; M5 one-shot Common Startup with matching receipt/HKU proof then privileged owned cleanup; M6 **client-approved** persistent last-resort mode, explicitly retired by an administrator. Don't imply M5 covers future users. Do not edit printer IPs, infer print-server identities, use `Utilities/Map-Printer.ps1` or `Add-Printer -ConnectionName` as an alternative mapping authority, or leave uncontrolled Startup helpers behind.
5. **If code repair is indicated:** use TokenCorridor's **current** prompt registry/resolver, not guessed P-number semantics: P04 to factor collisions/dependencies, P07 for bounded code/tests/docs/CI/PR convergence, P82 for hypothesis → working prototype → measured result → refinement, and P08 for real runtime observation and protected known-good controls. A pure question or missing physical access does not need speculative implementation. Preserve unrelated work, don't rewrite historical archived VBS or duplicate the mapper. Add a synthetic failing fixture from the classification, make the smallest safe repair, then rerun the failing gate and at least one protected known-good control. Merge to refreshed main when permitted and gates pass; distinguish **code merged** from **controller updated** from **standard-user observed**.
6. **When a real field fix is requested:** no broader fleet execution or rollback from a chat/issue report alone. Prove exact approved host + queue + organization/site profile + authority + current runtime and driver/security posture, complete preview and bounded one-host canary, and obtain legitimate operator/client authorization before mutation. Keep the Windows protected network/VPN posture intact; no new data collection just to satisfy a plan. A temporary mitigation must use a previously tested, approved field path, never direct-IP or a blind script. After deployment, verify intended standard-user HKCU/HKU queue and **a second distinct standard-user login** for durable coverage; confirm owned task/Startup/agent cleanup and a known-good mapping regression check. Physical printing is a separate observation.
7. **Response:** answer the immediate technician problem first with **CURRENT OBSERVATION / CLASSIFIED FAILURE / SAFE NEXT ACTION / REPAIR STATE**. If a repo change was made: **CHANGED | PROVED | NEXT** with exact branch/commit/PR/CI and installed/live proof ceiling. If blocked: **BOUNDARY | IMPACT | PROVED | RECOVERY | NEXT**. A hypothetical cause is not an observed incident. Every actual recurring bug must get a durable fixture and guard in its canonical owner, not only a revised agent instruction.

## Privacy and proof fixtures

- The **public-safe handoff** contains only a controlled symptom label, allowlisted evidence states, an opaque random incident ID, instructions, and explicit unproved status.
- The local finding input is a **private** event only; its `evidence_ref` is a local path and must never enter public PRs, issue comments, logs or telemetry.
- A technician's incident does **not** automatically trigger an agent, GitHub Action repair, ticket submission, deployment or external alert. It becomes agent work when the technician sends their query/handoff to an authorized agent with repository access.
- Evidence hidden behind client network controls is *not* made accessible through a generic agent plugin. Unsupported access is an explicit proof boundary, not grounds to ask the technician for secrets or publish records.

## P82 experimental admission for this incident UX

**Hypothesis:** with only Windows PowerShell 5.1, a tech can produce a deterministic, sanitized agent handoff from a failed printer workflow without elevation or network calls. **Baseline:** unstructured screenshots/log transcription and ambiguous repair handoffs. **Prototype:** `Report-NorthwellPrinter-Issue.cmd` → `scripts/Invoke-SasPrinterFieldIncident.ps1`. **Measure:** Windows parsing; fixture command succeeds in temporary local directory; exact controlled symptom taxonomy and allowed evidence state; synthetic hostname, user, queue and secret markers absent from safe handoff; invalid paths denied; existing field printer suite unaffected. **Decision:** promote only if latest-head CI passes; field usability needs separate real technician observation. Preserve the last known good version if a check fails.
